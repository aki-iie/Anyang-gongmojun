## 1. 한 줄 요약

진단 결과를 Firestore에 남기는 경로를 만들었다. **지원을 접수한 건은 주소까지 포함해 `diagnoses`에**, **접수하지 않은 건은 주소 없는 익명 통계로 `stats`에** 기록한다.

---

## 2. 왜 바꿨나

바꾸기 전에는 진단 결과가 어디에도 남지 않았다. 결과 화면에 뜨던 "접수번호 AY-######"도 실제로는 브라우저가 `Math.random()`으로 만든 숫자였고, 아무 데도 전송되지 않았다. 공무원이 볼 데이터가 애초에 존재하지 않았다는 뜻이다.

두 번째 이유는 검증이다. 위험 판정이 난 집만 저장하면 "위험한 집만 모아놓고 위험하다고 한 것"이 되어, 판정이 실제로 갈라지는지 보일 수 없다. **안전으로 나온 집의 분포가 있어야 대조군이 생긴다.** 그래서 모든 진단을 남기되, 동의를 받지 않은 건은 개인을 식별할 수 없는 형태로만 남기기로 했다.

## 4. 데이터 모델

### 컬렉션을 나눈 기준은 등급이 아니라 **동의 여부**다

등급(위험/경고/안전)으로 컬렉션을 나누자는 안이 있었지만 택하지 않았다. Firestore에서 컬렉션은 폴더가 아니라 이름표일 뿐이라 계층·비용·속도 이득이 없고, 나누면 오히려 손해가 생긴다. 전체 집계를 하려면 여러 컬렉션을 읽어 합쳐야 하고, 보안 규칙과 대시보드 코드가 등급 수만큼 늘어난다. 결정적으로 **등급은 고정된 값이 아니다.** 판정 기준을 한 번이라도 손보면 문서의 등급이 바뀌는데, 컬렉션이 나뉘어 있으면 문서를 지우고 다시 만들어야 한다. 등급은 `level` **필드**로 두고 쿼리로 거른다.

| 컬렉션 | 대상 | 동의 | 위치 정보 |
|---|---|---|---|
| `diagnoses` | 지원 접수한 건 | 필수 (수집·이용 + 제3자 제공) | 도로명주소 + 상세주소 + 정확 좌표 |
| `stats` | 진단을 끝낸 **모든** 건 | 불필요 (익명) | 100m 격자 + 구(區)만 |

### `diagnoses` — 지원 접수

동의 2건, 위험 판정(`위험`/`주의`), 안양시 좌표 범위. 이 세 가지를 **서버가 다시 검사**한 뒤에만 기록한다. 클라이언트가 보낸 값을 그대로 믿으면 위조 요청으로 대시보드에 쓰레기가 쌓인다.

```
location   lat, lon, address, detail, district(만안구|동안구), dong(null)
flood      covered, inMap, seg, predCm, traceCm, depthCm, basis
slots      답한 12슬롯만
diagnosis  surface{...}, backflow{...}, warnings[], actions[], quality{...}
level      위험 | 주의 | 확인필요 | 안전   ← 서버 파생
consent    { provide: true, priority: true }
status     미확인 | 확인중 | 지원연계완료
ticket     AY-######   ← 서버 발급
createdAt
```

### `stats` — 익명 통계

결과 화면에 도달하면 자동으로 한 건 남는다. **개인을 식별할 수 있는 값은 넣지 않는다.** 주소도, 상세주소도, 정확한 좌표도 저장하지 않는다. 좌표는 서버가 100m 격자로 바꾼 뒤 원본을 버리고, 주소는 요청 본문으로 잠깐 올라오지만 구(區)만 뽑고 버린다.

```
level, surface, backflow
grid       { id: '100m_41507_112281', lat, lon, cellM: 100 } | null   ← 셀 중심 좌표
district   만안구 | 동안구 | null
depthCm, predCm, traceCm, basis, inMap, covered
slots      집 구조 답변 (식별 불가)
unknownCount, reliable
createdAt
```

격자 크기는 `scripts/DS2_spatial_grid_analysis.ipynb`의 `CELL_M = 100`과 같게 맞췄다. 나중에 격자별 분포를 그 공간분석에 그대로 얹을 수 있다. 여유를 더 두고 싶으면 `functions/save.js`의 `CELL_M`만 키우면 된다.

### `level` — 표시용 파생값이지, 판정이 아니다

엔진(`diagnose.ts`/`diagnose.py`)은 **일부러 단일 점수를 만들지 않는다.** 경로 A(지표 유입)와 경로 B(역류)는 막는 설비가 달라서 따로 판정한다. `level`은 분류·집계를 위해 서버가 두 상태에서 파생시킨 라벨일 뿐이고, **판정 근거로 인용하면 안 된다.** 규칙은 `functions/save.js`의 `levelOf()` 한 곳에만 있다.

| 레벨 | 조건 |
|---|---|
| 위험 | `surface === '유입가능'` 또는 `backflow === '매우미흡'` |
| 주의 | `backflow === '미흡'` |
| 확인필요 | 둘 중 하나라도 `'확인필요'` |
| 안전 | `surface === '방어가능'` 이면서 `backflow === '양호'` |

**확인필요를 안전에 섞지 않는다.** 모르는 것을 안전으로 분류하면 "저기는 괜찮다더라"가 되어 버린다. 엔진이 `uncertain`을 다루는 원칙과 같다. 기존 `needsSupport`(접수 버튼 노출 조건)는 `위험 ∪ 주의`와 정확히 같다.

## 5. 동작 변화

| | 이전 | 이후 |
|---|---|---|
| 접수번호 | 브라우저가 `Math.random()`으로 생성 | 서버가 Firestore 기록에 성공했을 때만 발급 |
| 접수 결과 | 아무 데도 전송되지 않음 | `diagnoses`에 문서 1건 생성 |
| 접수 실패 | 실패 개념 자체가 없음 | 모달에 사유 표시, 재시도 가능 |
| 진단 완료 | 아무것도 안 남음 | `stats`에 익명 기록 1건 (등급 무관) |
| 동의 모달 | 체크박스 문장 2개 | 고지 4항목 표 + [필수] 2건 + 전체동의 + 거부권 안내 |
| 사진 | "동의 없이는 어디에도 전달되지 않습니다" | "진단에만 쓰이고 저장되지 않습니다" (실제 동작과 일치) |

접수번호가 서버 발급으로 바뀐 덕에 **화면에 접수번호가 보이면 문서가 실제로 생긴 것**이라고 믿을 수 있다. 이게 지금 가장 빠른 확인 방법이다.

## 6. 동의 절차

개인정보보호법이 요구하는 네 가지를 모두 화면에 띄운다 — 수집 항목, 수집·이용 목적, 보유·이용 기간, 거부 권리와 그에 따른 불이익. 체크박스만 두고 표를 생략하면 고지 의무를 채우지 못한다.

| 항목 | 내용 |
|---|---|
| 수집 항목 | 주소(도로명·상세), 위치 좌표, 진단 문답 답변, 진단 결과 |
| 수집·이용 목적 | 반지하 침수 피해 예방 설치 지원사업 대상 검토 및 안내 |
| 보유·이용 기간 | **영구 저장** |
| 제공받는 자 | 안양시청 재난안전과 |
| 제공 목적 | 설치 지원 우선순위 검토 및 현장 확인 |

체크박스는 [필수] 2개(수집·이용 / 제3자 제공)에 전체동의 하나. 거부 시 안내는 "설치 지원 접수만 제한되고, 진단 결과를 보시는 데에는 아무 영향이 없습니다"로 명시했다. 이름과 연락처는 수집하지 않는다.

문구는 전부 `src/content.ts`의 `CONSENT` 한 곳에 있다. 보유 기간을 바꾸려면 `CONSENT.table` 한 줄만 고치면 화면이 따라온다.

`stats`는 동의 대상이 아니라 **고지** 대상이다. 수집 전에 알려야 하므로 주소 입력 단계와 촬영 안내에 `STATS_NOTE`를 띄우고, 결과 화면에서 다시 한 번 알린다.

## 7. 검증한 것

타입 검사(`npx tsc -b`)와 `src` 전체 ESLint가 0 에러·0 경고로 통과했고, `functions/index.js`가 정상 로드되는 것도 확인했다. 백엔드 검증 로직은 Node로 직접 돌려 아래를 확인했다.

- 네 등급(위험·주의·확인필요·안전)이 모두 `stats`에 기록된다
- `stats` 문서에 `address` 필드와 `lat` 필드가 **실제로 존재하지 않는다**
- 안양시 밖 좌표는 격자 없이(`grid: null`) 집계만 남는다
- 동의 없이 `stats`는 통과하지만 `diagnoses`는 거부된다
- 위험 판정이 아닌 건(`방어가능` + `양호`)은 `diagnoses` 저장이 거부된다
- 서울 좌표, 좌표 누락, 상태값 위조가 모두 400으로 거부된다
- 슬롯에 끼워 넣은 알 수 없는 키가 버려진다
- 100m 안쪽의 두 지점이 같은 격자 셀로, 300m 떨어진 지점이 다른 셀로 떨어진다

빌드(`npm run build`)는 macOS에서 실행해야 한다. 작업에 쓴 셸이 리눅스라 esbuild 바이너리가 맞지 않아 타입 검사까지만 돌렸다.

## 8. 배포

```bash
cd ~/"안양 공모전 웹"
npm run build
firebase deploy --only firestore:rules,functions,hosting
```

함수가 두 개 늘었으므로 `--only hosting`만 실행하면 프론트는 새 코드인데 서버에 `/api/save`·`/api/stats`가 없어 접수가 실패한다.

배포 후 확인: 안양 좌표로 진단을 끝까지 돌려 결과 화면까지 간 뒤 Firebase 콘솔의 `stats` 컬렉션에 문서가 생기는지 보고, "지원이 필요한 수준이에요"가 뜬 경우 접수까지 눌러 `diagnoses`에도 생기는지 확인하면 된다.

## 9. 남은 것과 한계

- **행정동(`dong`)이 비어 있다.** VWorld 지오코더에서 받아오지 않고 있어 항상 `null`이다. 필요하면 `functions/geocode.js`에서 응답의 `structure`를 확인해 채운다. 지금은 구(區)만으로 필터한다.
- **슬롯 값 검증이 느슨하다.** `save.js`는 12개 키만 걸러내고 값은 문자열 길이만 본다. enum의 단일 원천이 TypeScript(`functions/src/prompt.ts`)라 런타임 JS가 읽지 못한다. 명세가 바뀌었을 때 저장이 조용히 막히는 쪽이 더 위험하다고 보고 느슨하게 뒀다.
- **접수번호가 랜덤 6자리다.** 수백 건 규모에서는 충돌이 사실상 없지만, 완전히 막으려면 카운터 문서를 두거나 docId를 그대로 쓰면 된다.
- **중복 기록.** 같은 사람이 두 번 진단하면 `stats`에 두 건이 남는다. 세션 단위 중복 제거는 하지 않았다 — 격자별로 집계하면 큰 문제가 아니다.
- **관리자 대시보드(`/admin`)가 없다.** 지금은 Firebase 콘솔에서 직접 본다. 규칙상 읽기는 `admin: true` 커스텀 클레임 계정만 가능하므로, 대시보드를 붙일 때 그 계정 발급이 같이 필요하다.

## 10. 팀 공유 메모

**차동현** — 판정 엔진과 슬롯 명세는 한 줄도 건드리지 않았다. 다만 `functions/src/prompt.ts`의 슬롯 enum 값을 바꾸면 `functions/save.js`의 `SLOT_IDS`(키 목록)도 같이 확인해 달라. 그리고 `level`은 저장·집계를 위한 파생 라벨이고 새 판정 체계가 아니다 — 두 경로를 따로 판정하는 설계는 그대로다.

**김황현** — 동의 고지 문구와 통계 안내 문구가 `src/content.ts`의 `CONSENT`·`STATS_NOTE`에 있다. 문구 수정이 필요하면 텍스트를 전달해 주면 반영하겠다. 특히 보유 기간(접수일로부터 1년)은 담당 부서 확인이 필요한 항목이다.
