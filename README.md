# 잠길까 — 안양시 반지하 침수 위험 진단

2026 안양시 공공데이터·AI 활용 대학생 경진대회 출품작.
반지하 거주자가 **집 사진 3장과 위치**를 넣으면, AI가 12가지 구조·배수 항목을 확인하고 **도시침수지도(예측)·침수흔적도(실측)** 의 침수심과 맞대어 **물이 들어올 길 두 가지(지표 유입 / 역류)** 를 따로 판정하는 웹 서비스.

## 1. 사용자가 겪는 흐름

**모바일** (실제 사용자 기준)

```
1단계 · 우리 집 위치      주소 검색 또는 현재 위치 → 지도로 확인
2단계 · 사진 3장          현관 턱 → 창문 → 골목 (카메라 바로 실행)
3단계 · 문진              12문항. 사진으로 확신한 항목은 "맞나요?" 한 줄 확인
4단계 · 결과              경로 A·B 판정 + 침수지도 오버레이 + 조치·행동요령 + 후속 대화
```

**데스크톱**은 1·2단계가 한 화면에 함께 나온다.

### 지도는 두 번 나오고, 역할이 다르다

- **1단계** — 배경지도 + 핀만. *"여기가 우리 집이 맞나요?"* 를 확인하는 화면이라 침수 구역을 덮지 않는다.
- **4단계** — 같은 지도에 예측 레이어(파란 면)가 얕은 등급부터 차오르고, 실측 흔적(붉은 점선)이 그 위에 얹힌 뒤, 핀 위에 판정 침수심 배지(`실제 침수 기록 · 33cm`)가 새겨진다.

## 2. 판정은 이렇게 나온다

**점수를 매기지 않는다.** 반지하에 물이 들어오는 길은 두 가지고, 막는 설비가 서로 다르다.
물막이판은 역류를 못 막고, 역류방지밸브는 지표 유입을 못 막는다. 그래서 따로 판정한다.
판정 엔진은 `src/utils/diagnose.ts`(= `scripts/diagnose.py`, 차동현). LLM은 값 추출만 하고 판정은 엔진이 한다.

| 경로 | 방법 | 결과 |
|---|---|---|
| **A 지표 유입** | `판정 침수심(cm) − 가장 약한 개구부의 방어높이(cm)` — 물리적 뺄셈 | 유입가능 / 방어가능 / 확인필요 |
| **B 역류** | 확률은 내지 않는다. 역류방지밸브 유무 + 전조 징후(배수 지연·이상음·역류 경험)를 센다 | 양호 / 미흡 / 매우미흡 / 확인필요 |

모르는 값(`unknown`)은 추측하지 않고 **확인필요**로 둔다. 모르는 항목이 4개 이상이면 화면에 "판정이 불확실해요"가 뜬다.

### 판정 침수심 — 두 채널 중 큰 값

| 채널 | 성격 | 값 | 비고 |
|---|---|---|---|
| **A** 도시침수지도 | 예측 — 50년 빈도 강우 시 잠길 깊이 | 등급 → `SEG_DEPTH_CM` 환산 | N330=20 · N331=40 · N332=60 · N333=100 · N334=150cm **(가정값)** |
| **B** 침수흔적도 | 실측 — 실제로 잠겼던 깊이 | m × 100 | 변환표 없음 |

`depthCm = max(예측, 실측)`. 실측은 "실제로 이만큼 잠겼다"는 하한선이라 예측이 0이어도 버리지 않는다.
결과 화면에는 두 값을 출처와 함께 따로 보여준다 — 예) *예상 0cm (도시침수지도) · 실제 기록 33cm (2022년 8월) → 33cm 기준*.
흔적 폴리곤 **바깥 100m 안**이면 판정에는 넣지 않고 "근처에 침수 기록이 있어요" 경고만 띄운다.

> ⚠ **`SEG_DEPTH_CM` 은 공식 범례값이 아니다.** `scripts/DS2_spatial_grid_analysis.ipynb` 셀 7의 대표값을 그대로 쓴다.
> 근거가 확정되면 `functions/flood.js` 한 곳만 고치면 된다(노트북 값도 함께).

### 확정되지 않은 침수심을 어떻게 다루는가

`SEG_DEPTH_CM` 이 미확정이면 경로 A 판정 전체가 가정 위에 서게 된다. 그래서 **값을 확정하는
대신 값이 결론을 얼마나 좌우하는지**를 먼저 계산했다. `tools/defense_lattice.py` 로 재현한다.

**방어높이는 연속값이 아니다.** 개구부 방어높이를 정하는 슬롯은 네 개(현관 턱 · 물막이판 ·
창문 하단 · 창문 차수막)뿐이고 전부 범주형이다. 그래서 가능한 조합이 **80가지**, 실효
방어높이가 가질 수 있는 값은 **10개**로 끝난다.

| 실효 방어높이 | 0 | 3 | 8.5 | 17 | 25.5 | 30 | 33 | 38.5 | 47 | 55.5 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 조합 수 | 17 | 7 | 14 | 12 | 10 | 8 | 3 | 5 | 3 | 1 |
| 누적 % | 21.2 | 30.0 | 47.5 | 62.5 | 75.0 | 85.0 | 88.8 | 95.0 | 98.8 | 100 |

**판정은 계단 함수다.** `침수심 > 방어높이` 뺄셈의 답이 바뀌는 지점은 위 10개 값뿐이다.
침수심을 18cm 로 잡든 25cm 로 잡든 결과가 같고, 25.5cm 선을 넘는 순간 62.5% → 75.0% 로 튄다.
**정확한 침수심을 몰라도 어느 구간에 있는지만 알면 결론이 나온다.**

**입력을 거칠게 받은 것이 이걸 가능하게 했다.** 현관 턱을 "신용카드 몇 개 높이" 로 묻는 건
사진 한 장으로 cm 를 잴 수 없어서 생긴 한계였다. 그런데 그 덕에 방어높이가 10개 값으로
고정됐다. 줄자로 재서 연속값(7.3cm 같은)으로 받았다면 조합이 무한해지고 침수심 1cm 차이가
계속 결과를 뒤집었을 것이다. **한계가 미확정 값을 견디는 구조를 만들어 준 셈이다.**

> **눈금은 실측에 맞춰 정했다.** 처음에는 "카드보다 낮음/비슷/높음" 으로 물었는데,
> 충훈동 34가구 실측을 대조해 보니 아래 두 칸(`없음`·`카드보다낮음`)에 **0가구**,
> 위 한 칸에 20가구(62%)가 몰렸다. 실측 현관 턱은 8.5 / 17 / 25.5 / 32cm — 전부
> 신용카드 긴 변(8.56cm)의 정수배로 관찰됐다. 그래서 **"카드 몇 개"** 로 바꿨다.
> 창문도 같은 문제였고(`땅보다높음` 20cm 한 칸에 8.5~25.5cm 가 전부 들어가
> 침수심 20cm 에서 7가구를 안전하다고 잘못 판정), 지면보다 낮게 박힌 창이 실재하므로
> `땅보다낮음` 은 유지한 채 지면 위쪽만 카드 개수로 나눴다. 재현: `tools/defense_lattice.py`

**다만 계단 구조만으로는 부족하다.** 어느 계단에 서 있는지는 알아야 한다. 그 범위를 채워 주는
것이 채널 B다 — 안양시 침수흔적 8건의 실측 침수심이 **9.3 ~ 33.0cm**(2022년 8월, 전부 내수침수)다.
이 구간을 대입하면 가능한 조합의 **47.5 ~ 85.0%** 가 유입가능으로 판정된다. 충훈동 현장조사
34가구를 대입하면 조합별 실제 빈도로 가중해 "조사 N가구 중 M가구" 형태로 다시 낸다.

즉 결론은 **판정의 계단 구조**와 **안양 실측 침수심 범위**가 합쳐져 나온다. 도시침수지도 등급
환산값 하나에 의존하지 않는다.

> 확률강우량표에서도 같은 방식을 썼다 — 2022년 8월 호우의 재현기간을 하나로 확정하지 않고
> 50~150년 민감도 범위로 제시했다. **모르는 값을 억지로 확정하지 않고 범위로 다루는 것**이
> 이 프로젝트의 일관된 방법론이다.

**부수적으로 나온 결과 ①** — 방어높이 0cm(어떤 비에도 즉시 유입) 조합 17개 중 10개가
`현관 턱 없음 + 물막이판 미설치` 다. 현관이 뚫려 있으면 창문을 아무리 높여도 실효 방어높이는
0이다. **현관 물막이판이 단일 설비로는 효과가 가장 크지만 안양시 미지원 품목이다.**

**부수적으로 나온 결과 ②** — 그렇다고 물막이판 하나로 끝나지도 않는다. 물막이판을 설치한
40개 조합 중에서도 안양 실측 침수심 범위에서 **30.0 ~ 70.0%** 가 여전히 유입가능이다
(창문 하단이 낮으면 실효 방어높이는 창문이 정하기 때문이다). 게다가 **경로 B(역류)는
물막이판이 손대지 못하는 축**이다. 품목 하나를 일괄 배포하는 방식으로는 닿지 않는 가구가
남는다는 뜻이고, **가구별로 어느 경로가 열려 있는지를 먼저 확인해야 한다**는 근거가 된다.

### 지원 접수 버튼
경로 A **유입가능** 또는 경로 B **미흡 이상**이면 뜬다. 조치 목록에서 안양시 지원 품목(창문 차수막·배수 펌프)과 미지원 품목(현관 물막이판·역류방지밸브)을 색으로 갈라 표시한다.

> **사진만으로 침수 정도는 판단할 수 없다.** 사진은 *"물이 들어오기 쉬운 구조인가"* 를 답하고, 침수지도는 *"이 자리에 물이 얼마나 차는가"* 를 답한다. 그래서 둘 다 필요하다.

## 4. 개발과 배포

```bash
npm install          # 최초 1회
npm run dev          # 로컬 개발 서버 (저장하면 즉시 반영)
npm run lint         # 코드 점검 — 현재 오류 0 · 경고 0
npm run build        # dist/ 생성 (tsc + vite)
```

### 배포

```bash
# src/ 를 고쳤으면
npm run build && firebase deploy --only hosting

# functions/ 를 고쳤으면
firebase deploy --only functions
```

**`npm run dev` 에는 `/api/*` 가 없다.** 화면 문구·레이아웃만 볼 때 쓴다.
서버까지 붙여서 배포본과 똑같이 확인하려면 빌드 후 에뮬레이터를 **5200번**으로 띄운다 (서버 origin 허용 목록에 있는 포트. 5000번은 macOS AirPlay가 쓴다):

```bash
npm run build && firebase serve --only functions,hosting --port 5200
# → http://localhost:5200/?lat=37.40501&lon=126.89803   (충훈로101번길 시연 좌표)
```

**배포 후 화면이 안 바뀌면** `index.html` 캐시다. 주소 뒤에 `?v=2` 를 붙이거나 강력 새로고침하면 된다.

| 용도 | 설정 |
|---|---|
| 사진 판독 (Vision) | temp 0.2, JSON 모드, 25초 제한. 사진 7개 항목을 확신할 때만 `high` |
| 자유 텍스트 → 슬롯 값 | temp 0, **json_schema strict**, **8초 제한** (로컬 매칭 실패 시에만) |
| 되물음 설명 · 결과 대화 | temp 0.4 / 0.7 |

**실측 비용 — 진단 1회 약 $0.0066 (9원).** prompt 토큰 42,000개 중 대부분이 사진이다. 업로드 시 긴 변 1024px로 줄이면 비용·속도가 크게 개선된다(미적용).

AI 응답은 `normalizeVLM()` / `parseExtraction()` 을 반드시 통과한다. 판정 엔진의 허용 값(`ALLOWED`) 밖이면 `unknown` 으로 강제되어 **문진에서 다시 묻는다.** Vision이 실패하거나 늦으면 판독 없이 12문항을 전부 묻는다.

### 문진이 막히지 않는 세 경로
버튼 클릭 · 자유 텍스트 · 건너뛰기 모두 `commitAnswer()` 하나로 모인다.
자유 텍스트는 로컬 매칭 → 실패 시 AI 추출. 애매하거나 **8초를 넘기면 선택지 버튼으로 폴백**한다.
되묻는 질문("물막이판이 뭐예요?")은 설명한 뒤 같은 질문으로 돌아온다. 건너뛰면 `unknown` 이 되어 확인필요로 판정된다.

### 키 보안
- **클라이언트**: `getApiKey()` 가 `import.meta.env.DEV` 로 게이트되어, 배포 빌드에서는 `() => null` 로 상수 폴딩된다. **번들에 AI 키가 들어가지 않는다** (매 배포마다 확인).
- **배포본**은 `/api/llm` 프록시를 탄다. 서버 키는 `functions/.env`.
- **프록시 가드레일**: 모델 화이트리스트(gpt-4o-mini만) · origin 검사 · 메시지 40개 상한 · max_tokens 1200. 외부 origin 403, 허용 외 모델 400으로 검증됨.
- VWorld 키는 지도 타일용이라 클라이언트에 노출된다(지도 API 표준 관행).

## 6. 침수지도 연동

원본: 국가공간정보 **도시침수지도 30년·50년 빈도** SHP — 만안구(41171)·동안구(41173).
좌표계 **EPSG:5186**(KGD2002 중부원점) → WGS84 변환 후 `functions/flood*.json` 에 적재.

- 속성 `SEG_CODE` **N330~N334** 가 침수심 등급. **숫자가 클수록 깊다** — 면적(N330 8.35km² → N334 0.001km²)과 폴리곤 포함관계로 확인.
- **각 등급의 실제 cm 구간은 아직 확정되지 않았다.** 현재 `SEG_DEPTH_CM`(20/40/60/100/150cm)은 대표값 가정이다. 원본 배포처 범례를 확인하면 `functions/flood.js` 의 `SEG_DEPTH_CM` 한 곳만 고치면 판정·화면·배지가 모두 따라온다.
- 폴리곤 조회는 **서버에서만** 한다. 지도 데이터 2.5MB는 브라우저로 내려가지 않는다. 조회 200회 7ms.
- 30년·50년을 각각 조회해 **보수적인 쪽(50년)** 을 판정 침수심으로 쓰고, 두 빈도를 화면에 함께 보여준다.

**검증** — 충훈동(석수동 충훈부) 좌표가 "침수 예상 구역 아님"으로 나온다. 기획서의 *"충훈동은 침수흔적도상 이력은 있으나 도시침수지도상 위험 지역이 아니다"* 와 일치하며, 아래 채널 B가 그 "이력"을 실제로 찾아낸다.

**침수 면적 비교** (단위 km², 만안+동안 합계)

| 등급 | 30년 | 50년 | 증가 |
|---|---|---|---|
| N330 | 8.353 | 8.608 | +3.1% |
| N331 | 0.465 | 0.517 | +11.2% |
| N332 | 0.085 | 0.097 | +13.5% |

깊은 등급일수록 증가폭이 크다 — 비가 더 오면 넓어지기보다 **깊어진다.**

### 채널 B — 침수흔적도 (실제로 잠겼던 기록)

출처: **재난안전데이터공유플랫폼 `DSSP-IF-00117`** (JSON, 폴리곤 `GEOM` 포함).
전국 38,003건 중 **안양시 8건** (석수동 5 · 박달동 1 · 비산동 2). 좌표계 **EPSG:3857** → WGS84 변환 후 `functions/trace.json` (6.4KB).

```bash
SAFETYDATA_KEY=... python3 tools/build_trace.py     # 원본 재수집 → trace.json 재생성
```

- API에 **시군구 필터 파라미터가 없다.** 전량(1000건×39페이지)을 받아 `STDG_SGG_CD` 로 자른다. 원본 캐시(46MB)는 `.cache_trace` 에 남고 git 에는 올리지 않는다.
- 기록된 침수심(m)을 **cm로 그대로** 판정에 넣는다. 변환표가 없다. **반지하는 0.2m만 차도 실내로 들어온다.**
- 지도에는 **붉은 점선**으로 그린다. 예측(파란 면)과 겹쳐 보면 두 채널의 차이가 바로 읽힌다.

**왜 두 채널이 필요한가 — 충훈동이 그 증거다**

안양시 8건을 채널 A로 교차 조회한 결과다. **8건 중 6건(75%)이 예측지도 밖이다.**

| 법정동 | 행정동 | 건수 | 기록 침수심 | 채널 A(예측) | 판정 침수심 |
|---|---|---|---|---|---|
| **석수동** (충훈부 일대) | **충훈동** | **5** | 19.7 ~ 33.0cm | **모두 구역 밖** | **19.7~33.0cm (실측)** |
| 박달동 | 박달동 | 1 | 9.3cm | 구역 밖 | 9.3cm (실측) |
| 비산동 | 비산3동 | 2 | 12.8 · 12.9cm | N330 | max(N330, 실측) |

행정동은 `functions/dong.js` 가 좌표로 판정한 값이다. **법정동으로는 없는 「충훈동」이
행정동으로는 실재하며(옛 석수3동), 5건이 정확히 이 동에 떨어진다** — 주민이 부르는
이름과 지원사업 접수 단위가 모두 행정동이라 대시보드 필터는 행정동을 쓴다.

석수동 5건은 **충훈로101번길 · 와룡로3번길 · 석수로202번길 · 석수로212번길** — 모두 **충훈부** 일대다.
실제 주소로 조회하면 이렇게 나온다.

| 주소 | 채널 A(예측) | 채널 B(실측) | 판정 침수심 |
|---|---|---|---|
| 충훈로101번길 55 | 구역 밖 | 33.0cm | **33.0cm** |
| 와룡로3번길 34-7 | 구역 밖 | 26.2cm | **26.2cm** |
| 석수로202번길 7-12 | 구역 밖 | 24.9cm | **24.9cm** |
| 석수로212번길 26 | 구역 밖 | 24.9cm | **24.9cm** |

**충훈동은 2022년 8월 호우로 실제 33cm까지 잠겼는데, 도시침수지도는 "위험 없음"이라고 답한다.**
기획서의 *"충훈동은 침수흔적도상 이력은 있으나 도시침수지도상 위험 지역이 아니다"* 가 공공데이터로 그대로 확인된다.
예측지도 한 채널만 쓰면 충훈동 전체가 침수심 0cm로 나오고, 방어높이가 얼마든 **전부 "방어가능"** 으로 판정된다.
채널 B가 이를 되살린다.

> **빈도가 다르다** — 예측은 30·50년 빈도이고 실측은 2022년 8월 호우(약 90년 빈도 추정) 기록이다.
> 실측이 예측보다 크게 나오는 것은 오류가 아니라 정상이며, 그럼에도 큰 쪽을 판정에 쓰는 이유는
> 실제로 잠겼던 자리를 "예측 구역이 아니므로 안전"으로 답하지 않기 위해서다.

> **동 이름 주의** — 행정구역상 **충훈동이라는 법정동은 없다.** 충훈부는 **만안구 석수동**의 지역명이고,
> 충훈로·충훈고등학교가 그 일대에 있다. VWorld 지오코더에 "충훈동"을 넣으면 석수동 주소를 돌려준다.
>
> **OSM(Nominatim) 역지오코딩은 이 지역의 법정동을 박달동으로 잘못 준다.** 도로명(석수로212번길, 충훈로101번길)은
> 맞게 주지만 동 이름이 틀린다. 법정동 확정은 반드시 VWorld(국가 공식)로 해야 한다 — 오차 5~9m로 일치한다.
>
> 기록은 **2022년 한 해뿐**이라 표본이 얇다. 45가구 현장 실사가 이를 보강한다.
